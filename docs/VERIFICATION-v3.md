# Проверка версии 3

Дата: 18 октября 2026 года.

## Что исправлено

Пользователь подтвердил, что в его сети без VPN работают AniLibria и сайт `https://v14.vost.pw` в браузере телефона. KinoVibe не открывается также в браузере. Вторая версия плагина использовала отдельный адрес `api.animevost.org`; доступность веб-зеркала не означала доступность этого API.

В версии 3 AnimeVost переведён на веб-каталог, поиск и плеер официального зеркала. Ссылка на зеркало опубликована на [странице AnimeVost](https://animevost.org/zerkalo.html). API и старый статический CDN больше не требуются этому адаптеру. Сохранённые номера релизов и серий из версии 2 распознаются; прежний адрес API в настройках не переносится в поле веб-зеркала.

Обнаружена ошибка единиц времени: NiceHttp принимает `timeout` в секундах, а в исходном коде было `20_000`, то есть более пяти часов вместо 20 секунд. Это подтверждено исходниками и байткодом используемой NiceHttp 0.4.18. Значения исправлены во всех адаптерах. Общий HTTP-клиент обычных источников использует 12 секунд для запроса и дополнительный предел ожидания 13 секунд. Отмена пользователем сохраняется; сетевые ошибки показываются как ошибки источника.

Поиск AnimeVost выполняется по названиям (`titleonly=3`), до пяти страниц результатов, с общим бюджетом 16 секунд. Поиск по полному описанию вытеснял старые точные совпадения свежими нерелевантными карточками. Каталог листается обычными страницами сайта без фильтра по году. Аудит 3 601 релиза API относится к версии 2 и не объявляется новым аудитом веб-каталога.

Видеоссылки берутся из актуального веб-плеера выбранной серии. Адаптер не выполняет загруженный JavaScript. Перед выдачей плееру проверяются HTTP-ответ и MP4-сигнатура с устройства: до восьми вариантов, не более четырёх одновременно, три секунды на проверку. Общий бюджет получения и проверки потоков — 28 секунд. Недоступные CDN и HTML-страницы блокировки отбрасываются. URL с другим номером серии не допускается; качество определяется по пути файла, чтобы SD-резерв не объявлялся 720p.

KinoVibe теперь выключен по умолчанию вместе с HDRezka и Filmix. Его сетевой доступ у пользователя не объявляется восстановленным. Включить источник вручную можно в настройках расширения с перезапуском Cloudstream.

## Проверки

- 39 модульных и HTTP-контрактных тестов, включая реальный короткий таймаут NiceHttp, отмену вызывающим кодом, HTTP 503, HTML вместо MP4, закрытие HTTP-ответов, поиск на второй странице, историю версии 2, неверный релиз и исчезнувшую серию.
- Четыре отдельных HTTP/JVM-сценария реальных Kotlin-адаптеров: AnimeVost через веб-зеркало; KinoVibe — фильм/мультфильм, старый/текущий сериал, пагинация категорий. Доступность KinoVibe на проверочном компьютере не переносится на сеть пользователя.
- Для AnimeVost проверяются «Тетрадь смерти» (2006, 37 серий), «Монстр» (2004, 74 серии), «Форма голоса» (2016, фильм). Для сериалов проверяются первая и последняя серии. После встроенной проверки ссылок дополнительно читаются 4 096 байт в начале и со смещением 1 МиБ каждого возвращённого потока.
- Сборка `.cs3`, версия и класс входа в манифесте, контрольная сумма и состав DEX проверяются перед публикацией.

Для повторения сетевой проверки:

```powershell
.\gradlew.bat :Kadrograd:testDebugUnitTest -PliveSources --tests '*LiveSourcesCheck'
```

Результаты сетевых сценариев: [live-check-v3.json](live-check-v3.json).

## Что ещё не подтверждено

Факт открытия зеркала пользователем проверяет доступность сайта в браузере его телефона. Воспроизведение обновлённым плагином, скачивание и работа всех выдаваемых CDN через его Wi-Fi пока не проверены. HTTP/JVM-проверка использует другое сетевое окружение и не заменяет эту проверку.

Версия 3 устраняет неверный адрес каталога AnimeVost и чрезмерное ожидание. Она не снимает сетевые блокировки KinoVibe/HDRezka и не обеспечивает полный каталог всех фильмов и сериалов.

После обновления Kadrograd до версии 3 нужно перезапустить Cloudstream. По умолчанию должны отображаться AniLibria и AnimeVost. В настройках расширения у AnimeVost должен быть веб-адрес `https://v14.vost.pw`.
